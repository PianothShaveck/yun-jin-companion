# Project rules

Keep the interface minimal in Italian, English and Simplified Chinese. Prefer fewer visible controls and shorter labels; show optional controls only when relevant. Preserve existing data, preferences, shortcuts and published calendar assignments. Never rely on Esc or native title-bar controls alone to dismiss a window: provide an in-content mouse close/cancel action. Calendar account settings must remain modeless, and background synchronization must not activate windows, take keyboard focus or rebuild unchanged account controls.

Keep startup and idle CPU, memory, network and disk use low. Load optional features lazily; perform image decoding and network work outside the GUI thread. Never decode the calendar catalog to select daily artwork. Originals are fetched on demand and use a bounded cache. Calendar pulls run every five minutes; only actual edits to linked events, calendar selection and conflict resolution may schedule the five-second upload debounce. Generic agenda/alert display signals must never trigger network sync. No-change sync must not invalidate/rebuild the agenda. Account and conflict dialogs use one in-content close action without a duplicate native title bar. Passive tooltips must never receive focus or change a live panel's activation style.

English is the default; first launch offers English, Italiano and 简体中文. Preserve existing language choices. Translate every interface and installer message, while preserving user-entered text. Speech language remains independent.

Maintain complete, version-independent guides in all three languages. Update guides only for meaningful feature changes. README and release notes are concise English written for app users, with no development status or handoff material.

The approved public Desktop app identity in app/google-calendar-client.json is intentionally distributed so users can sign in without developer setup. It contains only the application client ID and Desktop client secret (public client parameters, not a user authorization). Do not commit other OAuth files, account access/refresh tokens, personal databases or credentials. User authorization tokens belong only in the operating system keychain. Do not publish or push without authorization. Run affected test modules in separate processes. Google simulations do not replace a real cross-device test before publication.
